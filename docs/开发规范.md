> 落笔级别的规则，队友可直接照做。与 [设计文档](./设计文档.md) 冲突时以本文档为准。

## 1. 仓库与目录规则

```
hmdev/
  docs/                          全部项目文档
  submission/                    交付物（报名表；后期 docx / PPT / 视频 / rar）
  apps/
    server/                      后端服务（可依赖 packages/*）
    web/                         Web 演示端（P5 有余量再做）
  packages/
    shared/                      类型与常量（唯一来源）
    data/
      sites.yaml                 档案清单与台账（唯一事实来源）
      sources/<id>.md            来源摘录
      drafts/<id>.yaml           AI 草稿
      sites/<id>.yaml            终稿
      assets/img/<id>-1.webp     图片
      assets/license.md          图片版权台账
  tools/
    pipeline/                    数据流水线（chunk / tokenize / embed / graph / similar / export）
    gen/                         TS → ArkTS 类型生成
  harmony/
    YellowRiverArchive/          端侧工程（独立于 pnpm workspace）
```

**依赖铁律**

| 规则 | 说明 |
|---|---|
| `packages/shared` 不依赖任何其他包 | 它是契约的根 |
| `apps/*` 可以依赖 `packages/*` | 单向 |
| `packages/*` 之间不互相依赖 | `data` 只被 `tools/pipeline` 读取 |
| 端侧工程不参与 pnpm workspace | 只通过生成物同步类型 |

## 2. Git 规范

| 项 | 规则 |
|---|---|
| 托管 | GitHub 私有仓 |
| 分支 | `main`（随时可演示）/ `feat/<模块>-<简述>` / `fix/<简述>` / `data/<城市>` |
| 禁止 | 直接推 `main`；任何情况下不 force push 已推送的共享分支 |
| 提交信息 | `<type>(<scope>): <subject>` |
| type 取值 | `feat` / `fix` / `data` / `docs` / `refactor` / `test` / `chore` |
| scope 取值 | `server` / `app` / `pipeline` / `shared` / `graph` / `sync` / `docs` |
| 提交示例 | `feat(app): 首页时间轴支持拖动切换时代`<br>`data(luoyang): 补齐二里头考古发现层`<br>`fix(sync): 修复冲突日志时间戳精度丢失` |
| 主题 | 中文，动词开头，不超过 50 字，不加句号 |
| 评审 | 每个 PR 至少 1 人；**改契约的 PR 必须两端各 1 人看过** |
| 里程碑标签 | 每阶段结束打 tag：`p0-done`、`p1-done` … |
| 推送频率 | 当日工作必推，不在本地堆积 |

**钩子分流**（`.githooks/` + `git config core.hooksPath .githooks`）

| 钩子 | 内容 | 耗时 |
|---|---|---|
| `pre-commit` | 暂存区文件格式化检查、密钥扫描（拦截 `.env` 与 key 字样）、`sites.yaml` schema 校验 | <3 秒 |
| `pre-push` | TS 类型检查 + 单测 + `devecocli check arkts` | 按需 |

## 3. TypeScript 规范（后端与工具链）

| 项 | 规则 |
|---|---|
| 格式化 | Prettier：单引号、无分号、行宽 100、尾逗号 es5 |
| 检查 | ESLint + `@typescript-eslint`；**禁止 `any`**；强制 `import type` |
| 命名 | 文件 kebab-case；类型 PascalCase；变量 camelCase；常量 UPPER_SNAKE |
| 错误处理 | 不用异常做流程控制；异步统一 `try/catch` 并返回结构化结果 |
| 日志 | 禁止 `console.log`，统一走 pino |
| 注释 | **中文注释，英文标识符**；只写"为什么"，不写"是什么" |
| 导入 | 禁止循环依赖；`packages/shared` 的类型用 `import type` 引入 |

## 4. ArkTS 规范（端侧）

| 项 | 规则 |
|---|---|
| 目录 | `pages/` `components/` `model/` `service/` `utils/` `constants/` |
| 组件命名 | 组件文件与组件同名，PascalCase；一个文件一个页面组件 |
| 状态装饰器 | `@State` 本地 ｜ `@Prop` 单向 ｜ `@Link` 双向 ｜ `@Provide/@Consume` 跨层 ｜ `@Observed/@ObjectLink` 对象 |
| 副作用 | **禁止在 `build()` 里做计算或 IO**，放 `aboutToAppear` |
| 分层铁律 | 页面禁止直写 SQL 或网络请求，必须经 `service/` 层 |
| 常量 | 不硬编码字符串，统一从 `constants/` 取 |
| 类型来源 | 数据模型只能从 `shared` 自动生成的 `.ets` 引入，**禁止手写** |
| 资源引用 | 图片用 `Image($rawfile('img/xxx.webp'))` 零拷贝引用，**不导入沙箱** |
| 注释 | 中文 |

## 5. 契约同步流程

```
① 改 packages/shared/src/models/*.ts（Zod schema 与类型）
        ↓
② pnpm gen:arkts      生成端侧 .ets 类型（文件头标「自动生成 禁止手改」）
        ↓
③ 通知两端适配
        ↓
④ PR 必须同时包含 shared 改动与生成物
```

**不得跳步**：手改生成物会在下次生成时被覆盖，且两端类型漂移难以排查。

## 6. 日志与错误码

| 项 | 规则 |
|---|---|
| 后端级别 | `info` 业务里程碑 ｜ `warn` 可恢复（含降级） ｜ `error` 需人工介入 |
| 端侧 | hilog，TAG 统一为模块名（如 `SearchService`） |
| 错误码 | `E1xxx` 端侧 ｜ `E2xxx` 云侧 ｜ `E3xxx` 数据 |
| 降级日志 | 每次触发降级必须打一条 warn，便于路演前排查 |

## 7. 测试要求

**必须写单测的纯函数**

| 模块 | 测什么 |
|---|---|
| 检索 | RRF 融合、结构化过滤、权重计算 |
| 同步 | LWW 冲突判定与合并、变更日志重放 |
| 图谱 | 最短路、PageRank、标签传播 |
| 数据 | Zod schema 校验、n-gram 查重 |
| 端侧工具 | 词典最大匹配、时间轴位置计算 |

- 运行：`pnpm test`
- UI 层不做自动化测试，用 `devecocli ui layout / screenshot` 手动验证**并留存截图**作为测试证据

## 8. 依赖与密钥

| 项 | 规则 |
|---|---|
| 新依赖 | PR 描述里说明理由与替代方案；**端侧依赖尤其谨慎**（影响 HAR 体积与兼容性） |
| 版本 | 用 lockfile 锁定；不手工改 lockfile |
| 密钥 | `.env` 不入库（`.env.example` 入库） |
| 密钥边界 | 不进聊天记录、不进截图、**不进演示视频** |
| 环境变量 | 见 [设计文档 §10.3](./设计文档.md) |

## 10. 构建运行速查（devecocli）

| 场景 | 命令 |
|---|---|
| 语法检查（一轮改动后跑一次） | `devecocli check arkts --fix` |
| 构建 | `devecocli build` |
| 部署运行（自带冒烟检查） | `devecocli run` |
| 改代码快速生效（增量部署） | 写 `.hvigor/changes.txt` → `devecocli run --apply changes.txt` |
| 单模块 | `devecocli run --module entry` |
| 看设备 | `devecocli device list` |
| 看日志 | `devecocli log --level E --follow` |
| 看崩溃 | `devecocli log --crash --bundle-name com.yellowriver.archive` |
| 查 UI | `devecocli ui layout --format json` ｜ `devecocli ui screenshot --path ./shots/a.png` |
| 操作 UI | `devecocli ui click --id xxx` ｜ `devecocli ui text "洛阳"` |
| 查鸿蒙文档 | `devecocli docs search <关键词>` |
| 签名（首次） | `devecocli auth login` → `devecocli signature generate --product default` |

## 11. 提交交付物前的合规检查

**以下内容不得出现在设计方案 docx、演示视频、PPT 中**：

- 学校名称、简称、校徽
- 师生姓名、学号、联系方式
- 队名（可出现在 rar 文件名中，但不出现在材料正文）
- 任何可识别参赛单位的标识

打包命名：`赛题一+黄河图志+华北水利水电大学长河拾遗队.rar`
