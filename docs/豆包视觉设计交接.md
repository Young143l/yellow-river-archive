# 豆包视觉设计交接文档

> 用途：把「黄河图志」的界面视觉设计交给豆包（图像生成），产出可直接参考的视觉稿。
> 使用者：项目负责人。拿到图后交回开发者复现为 ArkTS / Canvas 代码。
> 最后更新：2026-10-29

---

## 0. 三十秒说清这个项目

「黄河图志」是一个 HarmonyOS 应用，把河南段黄河沿线的文化遗产做成可离线浏览、
可检索、可追问、可在多台设备间同步的数字档案。

使用者是**文博爱好者与普通游客**，展示场合是**省级竞赛的现场答辩**。

界面的目标不是"信息密度高"，而是**安静、克制、有书卷气**——它应该像一本装帧讲究的
地方志，而不是一个效率工具。

## 1. 视觉基调（锁死，不要改）

### 1.1 色板

| 色名 | 色值 | 用途 | 占比 |
|---|---|---|---|
| 纸底 | `#F2EDE0` | 页面背景，米黄宣纸 | 大面积 |
| 纸面 | `#FBF8F0` | 卡片、浮层，比纸底略亮 | 中等 |
| 石青 | `#3D7288` | **主色**：选中态、按钮、链接、进度条、水 | 少量点缀 |
| 朱砂 | `#A2392B` | **印记色**：印章、时代标题 | 极少 |
| 赭石 | `#A97544` | 土色：城市名、连接线、河岸 | 极少 |
| 石绿 | `#5E8A6B` | 植被：两岸、事件节点 | 极少 |
| 墨色 | `#23303A` | 正文文字 | — |
| 次级墨 | `#5A6B74` | 摘要文字 | — |
| 三级墨 | `#8D9AA1` | 元信息、提示 | — |
| 分割线 | `#DED5C3` | 1px 细线 | — |

**配色纪律**：石青承担一切"可以点"的东西，朱砂只负责印章与时代标题。
不要让朱砂去做按钮——印章和按钮同色，两套语义就混了。

### 1.2 字体

- 中文字体：**思源宋体**（Noto Serif SC），衬线
- 标题字距加宽（`letterSpacing: 3`），有碑刻感
- 正文行高 1.7 左右，不要挤

### 1.3 排版原则

| 要 | 不要 |
|---|---|
| 大留白 | 塞满屏幕 |
| 细线分割（1px） | 粗分割、色块分割 |
| 卡片靠留白分层 | 卡片靠阴影分层 |
| 圆角克制（8-10px） | 大圆角、胶囊堆叠 |
| 少量点缀色 | 大面积彩色 |

### 1.4 负面清单（每条提示词都要带上）

```
不要：霓虹色、赛博朋克感、玻璃拟物、渐变按钮、彩色阴影、
emoji、深色背景、英文界面、圆角卡片层层堆叠、复杂插画堆砌、浓艳饱和色。
```

## 4. 豆包必须知道的边界

### 4.1 界面里的文字会是乱码，这是正常的

图像生成模型写不好成段中文。生成稿里的文字大概率是"鬼画符"或伪汉字。

**看构图、色彩、笔触、版式比例，不要看文字。** 文字由开发者在代码里写死。

### 4.2 不要指望它能画出准确的古建筑

如果让它画"开宝寺塔宋代原貌"，出来的塔大概率和真塔对不上。
所以本项目的插画一律走**写意**路线——概括、意态到位即可，不承诺形制准确。

## 5. 操作步骤

### 第 1 步：准备参考图

已经整理好放在 **`.shots/doubao-refs/`**，文件名带序号，按顺序上传即可：

| 文件 | 对应页面 |
|---|---|
| `1-首页-现状.png` | 首页 |
| `2-检索-现状.png` | 检索 |
| `3-图谱-现状.png` | 图谱 |
| `4-助手-现状.png` | 助手 |
| `5-我的-现状.png` | 我的 |

> `.shots/` 已在 `.gitignore` 中，不会进仓库——这些是供你上传给豆包的本机文件。

### 第 2 步：先只出首页那一张

1. 打开豆包，新建对话
2. **上传 `.shots/final-home.png`**，说明：「这是现在的样子，我想在此基础上优化」
3. 粘贴 §3.0 风格前缀 + §3.1 首页提示词 + §1.4 负面清单
4. 生成

### 第 3 步：确认风格后再出剩下四张

**关键**：把第 2 步里你最满意的那张图，作为参考图上传，
再说「请保持这张图的配色、笔触、版式风格，设计检索页」，然后粘 §3.2 的提示词。

这样五张稿才不容易风格漂移。

### 第 4 步：把图发给我

五张 PNG 打包发过来，或直接放进 `.shots/doubao/` 目录。

## 6. 验收清单

拿到图后先自己过一遍：

| # | 检查项 | 不合格的表现 |
|---|---|---|
| 1 | 底色是不是米黄宣纸 | 白色、灰色、渐变底 |
| 2 | 主色是不是偏青的蓝绿 | 鲜艳宝蓝、荧光青 |
| 3 | 有没有大片留白 | 塞满、拥挤 |
| 4 | 有没有渐变按钮、彩色阴影 | 有 → 直接返工 |
| 5 | 五张之间风格是否一致 | 一张古风一张科技风 → 返工 |
| 6 | 首页河流是否像"河" | 像蛇、像鱼、像光缆 → 返工 |
| 7 | 是否深色背景 | 有 → 返工（本项目是浅色宣纸底）|

**返工话术**：「配色偏离了，请严格用 #F2EDE0 米黄纸底、#3D7288 石青、#A2392B 朱砂，
不要任何渐变和阴影，大量留白。」

## 7. 拿到图之后开发者怎么用

```
豆包输出 5 张 PNG
      ↓
读图：量取构图比例、提取主色分布、观察笔触特征
      ↓
首页河流 → 改写 Canvas 的 riverX / riverHalf / 笔触参数
其余四页 → 调整布局比例、间距、层级
      ↓
截图与豆包稿并排对比，迭代 2-3 轮
```

### 为什么河流要代码复现而不是直接用图

| 方案 | 包体积 | 适应性 | 滚动联动 |
|---|---|---|---|
| **Canvas 程序化**（当前） | 0 KB | 任意屏高不失真 | 可随滚动变形 |
| 图片素材 | 每张 100-300 KB | 拉伸会变形 | 只能平移 |
| 视频 | 1-3 MB | 分辨率固定，可能裁边 | 无法与滚动速度同步 |

河流高度等于内容总高（会随后续 80 条内容变得很长），只有程序化绘制才不会失真。

## 8. 附：当前实现的河流参数（供开发对照）

```
河道中心线：三道正弦叠加
  riverX(y) = 55 + sin(y*0.0045+1.1)*8.5 + sin(y*0.0132+0.4)*4.2 + sin(y*0.0310+2.2)*1.8

河道半宽：随流程起伏
  riverHalf(y,h) = 35 * clamp(0.94 + 0.05*sin(y*0.0052+2.0) + 0.04*sin(y*0.0137+0.9), 0.84, 1.04)

结构：河漫滩（赭石浅沙）→ 3 条汊道（石青）→ 横带笔触 → 岸线（赭石）
      → 植被带（石绿）→ 水纹短弧（白青）→ 首尾纸色淡出

已知问题：宽窄变化与汊道形态仍偏呆板，这是本次最希望豆包给出新方向的部分。
```
