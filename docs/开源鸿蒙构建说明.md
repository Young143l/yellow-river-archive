# 开源鸿蒙（OpenHarmony）构建说明

本项目以开源鸿蒙为目标平台，`build-profile.json5` 中 `runtimeOS` 为 `OpenHarmony`。
不使用任何 HMS（华为专有服务）能力。

## 一、环境要求

| 项 | 版本 | 说明 |
|---|---|---|
| DevEco Studio | 26.0.0 | 提供 hvigor 6.26.x |
| OpenHarmony SDK | 26.0.0（26.0.0.38） | 必须经 SDK Manager 安装 |
| JDK | 21 | 签名工具 `hap-sign-tool.jar` 需要 |

SDK 安装路径：`~/Library/OpenHarmony/Sdk/26.0.0/`，同级的 `licenses/` 目录是
hvigor 认可的登记凭据，缺了会报 `00308018 SDK management mode has changed`。

## 二、与 HarmonyOS 工程的三处差异

1. **版本号写字符串**
   API 26 起 `compileSdkVersion` / `compatibleSdkVersion` / `targetSdkVersion`
   必须是 `'26.0.0'` 这样的字符串；API 10–25 才是数字。

2. **modelVersion 必须是 6.0.0 及以上**
   `hvigor/hvigor-config.json5` 与项目级 `oh-package.json5` 两处都要改。
   否则报 `00303315`：当前 modelVersion 不支持字符串版本号。

3. **`deviceTypes` 用 `default` 而不是 `phone`**
   OpenHarmony SDK 的 `ets/api/device-define/` 里没有 `phone.json`，
   用 `phone` 会报 `00303060`「systemCapability 集合交集为空」。
   手机在 OpenHarmony 的表述里归入 `default`。

## 三、`local.properties`

```properties
sdk.dir=/Users/<你的用户名>/Library/OpenHarmony/Sdk
```

**注意指向 `Sdk` 而不带版本号。** hvigor 会自己拼 `<版本>/<组件>`
（见 `abstract-component-loader.getLocation`）；写上版本号会被判成
「组件位置不对」，报同一个 `00308018`。

该文件已在 `.gitignore` 中，不进仓库。

## 四、构建

```bash
cd harmony/YellowRiverArchive
devecocli build
# 产物：entry/build/default/outputs/default/entry-default-unsigned.hap
```

## 五、签名

hvigor 的 `signingConfig` 要求密码是 DevEco 加密后的 32 位密文，命令行生成不出来，
所以拆成两步：

```bash
tools/sign-openharmony.sh            # 构建 + 签名 + 校验
tools/sign-openharmony.sh --sign-only # 只签已有的 unsigned HAP
```

脚本用 OpenHarmony SDK 自带的官方测试证书链：

| 文件 | 用途 |
|---|---|
| `toolchains/lib/OpenHarmony.p12` | 密钥库，口令 `123456` |
| `toolchains/lib/UnsgnedReleasedProfileTemplate.json` | profile 模板 |
| `toolchains/lib/OpenHarmonyProfileRelease.pem` | profile 签名证书 |
| `toolchains/lib/hap-sign-tool.jar` | 签名工具 |

过程：填 profile（改 `bundle-name`、延长 `validity`）→ `sign-profile` 出 `.p7b`
→ `sign-app` 出签名 HAP → `verify-app` 校验。

产物：`entry/build/default/outputs/default/entry-default-signed.hap`（约 4.5 MB）

**证书是公开材料，不是私密凭据**，故 `signature/` 目录随仓库提交，方便评委复现。

## 六、踩过的坑

| 现象 | 原因 | 处理 |
|---|---|---|
| `00303034` 要求配 `compileSdkVersion` | OpenHarmony 不认 `targetSdkVersion` 单独存在 | 补 `compileSdkVersion` |
| `00306042` 版本号格式 | API 26 要求字符串 | 三处都写 `'26.0.0'` |
| `00308018` SDK management mode | ① SDK 未经 SDK Manager 安装 ② `sdk.dir` 带了版本号 | 用 SDK Manager 装一次；`sdk.dir` 指到 `Sdk` |
| `00303315` 不支持字符串版本号 | `modelVersion` 还是 5.0.5 | 两处升到 6.0.0 |
| `00303060` syscap 交集为空 | `deviceTypes` 用了 `phone` | 改 `default` |
| `sign-app` 报 `{SignAlg} param is incorrect` | 算法名写成 `SHA256WithECDSA` | 要小写 w：`SHA256withECDSA` |
| `sign-app` 报应是 cert chain | 用 `keytool -exportcert` 导出的是自签名证书 | 改用 profile 模板里内嵌的 `distribution-certificate` 作叶子，再拼 CA 与根 |
| hvigor 要求密码 ≥32 位 | 只接受 DevEco 加密的密文 | 放弃 `signingConfig`，改用脚本签名 |

## 七、可运行性

OpenHarmony 签名的 HAP **可以装进 DevEco 的 HarmonyOS 模拟器**（实测
HarmonyOS 7.0.0 / API 26），因此本地测试链路与交付链路是同一条，不需要双 product。

安装：

```bash
hdc install -r entry/build/default/outputs/default/entry-default-signed.hap
hdc shell aa start -a EntryAbility -b com.yellowriver.archive
```
