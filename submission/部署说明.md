# 黄河图志 · 云侧服务部署说明

本包只包含**云侧服务**（账号、检索、问答、图谱、同步、备份）及其依赖的工作区包，不含鸿蒙客户端。客户端已内置全部档案数据，断网也能用；云侧只承担「账号与个人数据云存储」与「RAG 检索问答」。

## 一、环境要求

| 项 | 要求 |
|---|---|
| Node.js | **≥ 22.5**（用到内置 `node:sqlite`，无原生依赖，不需要编译） |
| pnpm | ≥ 10 |
| 内存 | 1 GB 可用即可 |
| 磁盘 | 约 50 MB（含数据与向量） |

## 二、部署步骤

```bash
tar -xzf yra-server.tar.gz && cd yra-server
pnpm install                # 纯 JS 依赖，无编译
cp env.example .env         # 没有此文件则按下方模板自建
vi .env                     # 至少填两个 AI Key（不填也能跑，见第八节）
pnpm server
```

`.env` 模板（放到仓库根目录）：

```
SERVER_HOST=0.0.0.0
SERVER_PORT=8787

DASHSCOPE_API_KEY=
DEEPSEEK_API_KEY=

DASHSCOPE_BASE_URL=https://dashscope.aliyuncs.com
DEEPSEEK_BASE_URL=https://api.deepseek.com
EMBEDDING_MODEL=text-embedding-v4
EMBEDDING_DIM=1024
RERANK_MODEL=gte-rerank-v2
DEEPSEEK_MODEL=deepseek-chat
```

**`SERVER_HOST` 必须是 `0.0.0.0`**，默认 `127.0.0.1` 只有本机能访问。

首次启动自动建库（含 `accounts` 账号表）并导入预置数据，日志会打印
`数据导入完成：5 条目 / 57 片段 / ...`。

## 三、必须注意：反向代理要放行 WebSocket

问答走 `ws://<域名>/api/qa`，同步走 `ws://<域名>/api/sync`。Nginx 示例：

```nginx
location / {
    proxy_pass http://127.0.0.1:8787;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_read_timeout 300s;
}
```

## 四、账号体系（ADR-044）

**云端身份一律走 `/api/auth`。配对码已移除。**

- 注册与登录是同一个端点：名字不存在即注册，存在即验 PIN
- PIN 只存 sha256(盐 + PIN)，服务端无明文
- ws 同步、设备列表、备份/快照接口都要求 userId 属于已注册账号，
  否则返回 `401 E4012`（ws 拒绝并断开）
- 多设备 = 两台设备登录同一账号

## 五、接口清单

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/health` | 健康检查 |
| POST | `/api/auth` | 登录/注册（用户名 + 4-6 位 PIN） |
| GET | `/api/items` | 条目列表（支持筛选） |
| GET | `/api/items/:id` | 条目详情 |
| GET | `/api/items/:id/related` | 相关条目 |
| POST | `/api/search` | 混合检索（BM25 + 向量，RRF 融合） |
| GET | `/api/qa`（WebSocket） | 流式问答，带引用 |
| GET | `/api/graph/ranks` | 图谱 PageRank |
| GET | `/api/graph/communities` | 社区发现 |
| GET | `/api/graph/subgraph` | 子图查询 |
| GET | `/api/graph/path` | 两点间路径 |
| GET | `/api/graph/search` | 图内实体检索 |
| GET | `/api/items/:id/subgraph` | 条目邻域 |
| GET | `/api/sync`（WebSocket） | 双向同步（分批进度） |
| GET | `/api/sync/devices` | 已登录账号的设备列表 |
| POST | `/api/backup/snapshot` | 创建云端快照 |
| GET | `/api/backup/snapshots` | 快照列表 |
| POST | `/api/backup/snapshots/:id/restore` | 恢复快照 |
| DELETE | `/api/backup/snapshots/:id` | 删除快照 |
| GET | `/api/stats/usage` | AI 用量统计 |

## 六、进程守护

```ini
# /etc/systemd/system/yra.service
[Unit]
Description=Yellow River Archive API
After=network.target

[Service]
Type=simple
WorkingDirectory=/opt/yra-server
ExecStart=/usr/local/bin/pnpm server
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
systemctl enable --now yra
journalctl -u yra -f
```

## 七、数据与备份

- 数据库：`apps/server/data/yra.sqlite`（账号、同步数据、快照全在里面）
- 迁移或备份直接打包该文件即可；删掉重启会自动重建并重新导入预置数据

## 八、AI Key 建议填，不填也能跑

缺 Key 时服务正常启动，只在日志告警：

```
未配置 DASHSCOPE_API_KEY：语义通道与精排不可用，检索降级为纯 BM25
未配置 DEEPSEEK_API_KEY：问答生成不可用，/api/qa 只返回检索原文摘要
```

## 九、自检清单

```bash
# 0. 账号（返回 ok:true 与 userId 即正常）
curl -s -X POST http://127.0.0.1:8787/api/auth \
  -H 'Content-Type: application/json' \
  -d '{"username":"demo","pin":"1234"}'

# 1. 健康检查
curl -s http://127.0.0.1:8787/api/health

# 2. 检索
curl -s -X POST http://127.0.0.1:8787/api/search \
  -H 'Content-Type: application/json' \
  -d '{"query":"唐三彩","topK":3}'

# 3. 未注册身份应被拒（HTTP 401）
curl -s -X POST http://127.0.0.1:8787/api/backup/snapshot \
  -H 'Content-Type: application/json' \
  -d '{"userId":"u_ghost"}'

# 外网
curl -s https://<你的域名>/api/health
```
